## Phase 3 implementation boundary

The reader explicitly rejects non-default or nonnumeric leaf-page `UserUnit` values before returning metadata, thumbnails or tiles. `UserUnit` is not inherited from the Pages tree; unlike CropBox/Rotate, it remains a page-dictionary attribute (ISO 32000-1 Table 30). Default units keep the existing PDF-user-space annotation coordinates and page transforms. This aligns the supported boundary with annotation export without changing physical scale silently.

The local renderer patch propagates failed images (including inline and stencil images), Forms and masks through `Result`. Missing/unsupported XObjects and shadings, truncated stencil data and the audited Form/Type 3/soft-mask recursion failures also refuse a successful raster. Full-page, thumbnail and tile paths use the same policy. Breeze attaches the page number and shows a bounded page error plus a persistent status message; failed pixels are not cached. Valid pages remain navigable after a failed page, and source bytes are unchanged.

This phase addresses the reproduced R03/R05 defects. It is not general PDF fidelity acceptance: font substitution, colour-function and pattern fallbacks, annotation-appearance interoperability, decoder limits, representative corpus coverage and native Windows/Linux behavior remain separate gates. Export validates object preservation and supported geometry; copying a source with damaged drawing data is not proof that its existing content can be rendered correctly.
